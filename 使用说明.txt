AI工具合集 - 使用说明（统一工程 · 单一入口）
==============================================

【是什么】
  一个导航首页，汇总全部工具；所有工具已整合为**同一个网站**，只有**一个服务、一个端口（8080）**：
  - 导航首页        http://localhost:8080/
  - 达梦数据库查询  http://localhost:8080/dm
  - 旧LIMS查询(SQL Server)  http://localhost:8080/sqlserver
  - 数据看板        http://localhost:8080/board
  - 人员能力表梳理  http://localhost:8080/personnel
  - 一单一库核对(CMA)  http://localhost:8080/cma
  - 抽采样进度统计  http://localhost:8080/progress

  数据库账号密码只在后端一处配置（backend\.env），前端不再保存任何连接信息。

【怎么用】
  1. 开始：双击「一键启动.bat」，服务自动在后台启动并打开导航首页
  2. 使用：在导航首页点任意工具卡片即可进入（新标签页打开）
  3. 结束：双击「停止服务.bat」一键关闭

【一单一库核对：核对台账（留痕）】
  作用：每次核对都自动留痕，形成可追溯的台账，作为"检测能力持续符合 + 管理体系持续有效运行"的证据。
  用法：
    1. 进入 一单一库核对（http://localhost:8080/cma）
    2. 在「核对留痕信息」里填写 操作人 / 部门 / 核对用途（本机自动记忆，下次不用重填）
    3. 粘贴或上传标准号 → 点「开始核对」，结果出来的同时台账已自动记录（无需额外操作）
    4. 在页面底部「核对台账」中按 日期 / 关键词 / 结论 / 操作人 查询历史批次，
       点「查看明细」可看该批次逐条结论，并可补记「处置/复核说明」
    5. 点「导出台账 Excel」导出归档（含「批次汇总」+「核对明细」两个工作表）
  留痕内容：
    - 批次：批次号、核对时间、完成时间、操作人、部门、用途、输入来源、客户端IP、
            条数、在清单内/版本待确认/不在清单内/查询异常 数量、覆盖率、耗时、处置说明
    - 明细：输入标准号、平台标准号、标准名称、结论、匹配方式、平台备注、异常信息
  存放位置：backend\data\cma_ledger\ledger.sqlite（如需归档到其他盘，改 backend\.env 的 CMA_LEDGER_DIR）
  重要：台账只增不删（无删除入口），历史记录一经写入即固定；核对时即使台账写入异常，
        核对结果照常返回，页面会明确提示"台账写入异常"，避免"以为留了痕其实没留"。

【逐条处理意见（风险项强制闭环）】
  哪些条目必须写处理意见：
    ① 核对结果 = 版本不符·待确认
    ② 核对结果 = 不在清单内
    ③ 核对结果 = 在清单内 但平台有备注（"有备注"）
    其余条目（在清单内且无备注）无需处理，表格里显示"—"。
  在哪填（两个地方都能填）：
    1. 核对完成后，在「核对结果」表最右侧"处理意见"列直接填 → 点该行「保存」，
       或点上方「💬 保存全部处理意见」一次提交所有已填写的（按钮上会显示 需处理 n · 未填 m）；
    2. 事后在「核对台账」里点某批次的「查看明细」，在明细表的"处理意见"列补填或修改。
  未填会怎样：
    · 该行/该条目无提示色，台账批次行的「待处理」列、汇总卡「累计待处理」会统计出来（>0 标红）；
    · 勾选台账筛选区的「只看待处理」可一键定位到还没闭环的批次；
    · ⚠ 只要台账里还存在未填的处理意见，「⬇ 导出台账 Excel」会被**阻止**并提示还有多少条，
      自动切到"只看待处理"帮你定位——填完后才能导出（强制闭环）。
  说明：处理意见只保存意见内容本身，不记录填写人与填写时间（按需求确认）。
        它是"填写"性质的字段，允许修改覆盖；核对记录本身仍然只增不删。

【批次明细的三种视图（快速找到要填的行）】
  在「核对台账」点某批次「查看明细」后，明细区上方有三档视图（各带条数）：
    · 全部            —— 该批次所有条目
    · 只看需处理      —— 版本待确认 / 不在清单内 / 有备注 的条目
    · 只看待处理      —— 需处理且还没填处理意见的条目
  默认视图：该批次还有待处理项时默认落在「只看待处理」，直接呈现要填的行；
            已全部填写完则默认「全部」（几百条明细里找那几条待填，用这个视图最省事）。
  批量保存：明细区右侧「💬 保存已填的处理意见（n）」可一次提交本批次所有"填了但还没保存"的意见
            （n 为草稿与已存内容不同的条数；n=0 时按钮不可点），不必逐条点保存。
  提示：视图的条数按**已保存**的内容统计，所以正在输入的那一行不会中途消失；
        保存成功后该条会从「只看待处理」视图里消失（表示已闭环）。

【处理意见 / 处置说明的「历史记忆」下拉】
  作用：以前填过的措辞会作为候选积累下来，下次直接从下拉里选，不用重复手打，也保证同类问题措辞统一。
  在哪用（3 处，交互完全一样）：
    · 核对结果表 →「处理意见」列
    · 核对台账 →「查看明细」→ 处理意见列
    · 核对台账 →「查看明细」→「处置 / 复核说明」（批次级）
  怎么用：
    1. 输入框右边有个 `[n ▾]` 按钮（n = 历史上填过的候选条数），点它展开历史列表；
    2. 列表每项显示意见文本 + 使用次数 `×n`，按使用次数从多到少排列；
    3. 面板顶部可输入关键词即时过滤；点某一条 → **只填入输入框**（不会自动保存，可再修改）；
    4. 确认无误后点「保存」（或批量保存）才写入台账；
    5. 保存成功后候选列表自动更新，新措辞下次即可复用。
  说明：候选来自**全台账（跨批次）**已保存过的内容，含使用次数；不做预置模板、也不做历史删除。
        台账里没有任何历史时，面板会提示"暂无历史记录：先手动填写并保存，下次就能从这里选"。

【抽采样进度统计（/progress）】
  作用：把「已下达的任务量」与「实际抽采样完成量」放在一张表里对照，看每个合同、每个区县、
        每种重点监管品种（豇豆、芹菜、辣椒等）的进度；完成率 = 完成量 ÷ 任务量。
  四个页签：
    1. 数据看板    —— 总览卡片（总任务量/完成量/总完成率/覆盖区域数与合同数）、区域完成率对比图、
                      品类分布图、区域×产品类型动态明细表（含合计行/列、完成率色标）、按合同拆解、
                      完成量同步记录；右上「同步完成量」立即重算，「导出当前视图」导出 Excel。
    2. 任务量录入  —— 先选合同，再按「区域 × 产品类型」逐格填写；支持从 Excel 复制粘贴、
                      填满本列/全部填满、清空本行；支持模板下载、Excel 导入（逐行校验回显）、导出。
    3. 产品类型与区域 —— 产品类型即表头列：可新增/改名/填别名/设所属品类/排序/停用；
                      当前配置的是使用方下达口径的 15 个分组（农产品-豇豆、芹菜、辣椒 / 其他蔬菜 /
                      食用菌 / 水果 / 茶叶 / 小麦；畜产品-猪肉、猪肝 / 牛肉、牛肝 / 羊肉、羊肝 / 禽肉 /
                      鸡蛋、鹌鹑蛋 / 其他禽蛋 / 生鲜牛乳；水产品-七条鱼 / 其他水产）。
                      匹配顺序：样品名 → 样品名去括号后缀 → **样品类别名**；
                      名称里的顿号会自动拆成多个品种（「豇豆、芹菜、辣椒」三个都能命中）；
                      「其他X」这类兜底列，靠把**类别名写进别名**来接住剩余样品
                      （如「其他蔬菜」别名写 蔬菜|蔬果、「其他水产」别名写 鱼类|虾蟹类…）。
                      「未匹配样品」候选一键新增（同步时发现的高频样品名）；
                      区域可增删与启停（省例行会抽到苏州以外的区县，同步时自动登记）。
                      组合口径与兜底定义：一列可含多个品种（名称里写顿号，或把品种填进「成员品种」）；
                      「其他X」这类兜底列，把**样品类别名**填进「成员品种」即可（如 蔬菜|蔬果）——
                      因为匹配是"样品名优先"，兜底列只会接住没被具体列认领的样品。
                      快速定义：点「批量定义」把清单整段粘进来（每行 `品类-名称[:成员1|成员2]`，
                      连字符 - — – 都认），先「解析预览」再「确认定义」；改完点「重算完成量」即刻生效。
    4. 合同管理    —— 合同是统计的一级维度：同步时自动发现当年合同（**只登记编号**），也可手工预先录入；
                      合同一律按编号识别、界面上不显示名称（达梦侧合同名称为空），要写说明请填「备注」；
                      被任务量引用的合同/品种/区域不能删除（只能停用）。
  完成量怎么来的（重要）：
    · 取自本地 SQLite 镜像快照（F:/aitools-mirror/current.sqlite，每天 19:00 同步源库），**不是实时**；
      页面顶部显示「镜像数据 · 截止 时间」，同步记录里也有每次重算的时间与耗时。
    · 口径：按年（抽样日期 SAMPLING_DATE，为空按受理日期 ACCEPT_TIME）；完成量 = 去重样品数；
      区域取受检单位所在地的区县；产品类型按样品名称匹配（自动忽略全角括号后缀，如 豇豆（KH））；
      与「数据看板」一致地剔除了测试样品与练兵/方法确认合同（剔除数在同步记录里显示）。
    · 「未匹配产品类型」的样品：单独一列显示、并在提示条里给出数量，**不计入完成量与完成率**
      （否则没归类的样品会把完成率推高成假数字）；配置完产品类型后重新同步即会归位。
    · 「未指定合同」（质控等无合同编号样品）单独可查，不计入"全部合同汇总"。
  定时重算：默认每天 19:40（晚于镜像 19:00 同步）。改 backend\.env 的 PROGRESS_SYNC_AT（留空=只手动）。
  存放位置：backend\data\progress\progress.sqlite（产品类型/区域/合同/任务量/完成量快照/同步日志）；
            目录可用 backend\.env 的 PROGRESS_DIR 改到其他盘。

【数据库连接改了怎么配】
  只需修改 backend\.env（达梦 / SQL Server 的 IP、端口、库名、账号密码），其它都不用动。

【和以前有什么不同】
  - 以前：需要同时开 4000 中间池 + 3001/3002/3003/3005/3007 五个服务，共 7 个进程、7 个端口
  - 现在：只开 1 个服务（8080），同时提供所有页面与接口
  - 访问地址由「各端口分站」变为「同站不同路径」（左上表），功能与界面保持一致

【常见问题】
  - 页面打不开：双击「一键启动.bat」后稍等数秒；仍不行请看 _logs\8080.log
  - 提示未构建前端：在 frontend 目录执行 npm install && npm run build（一键启动脚本也会自动构建）
  - 一单一库核对需服务器能访问外网 cma.caqit.org.cn
